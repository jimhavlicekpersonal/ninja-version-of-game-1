## Device targets

- Windows 11 laptop (mouse, keyboard, trackpad), Google Pixel 7 (Chrome), iPhone (Safari); cheap Android phones are the worldwide target (`render/quality.ts` low profile). Touch first, safe areas, portrait and landscape; the bottom bar fits 320 px.
- Installable PWA (`base: './'`, `src/backend/pwa/sw.template.js`), deployed by `.github/workflows/deploy.yml` to GitHub Pages on pushes to `main`. Capacitor 8 wraps iOS and Android. The app display name is "Kagemura"; the bundle id is still the old one until new store listings exist (owner step).
- `npm run dev` / `npm run dev:lan`. `?sandbox` or `?debug` opens the testing sandbox (separate save, never online, time skips and the instant test store; `?debug` also exposes `window.tk`). The public web build has no store and runs on real time.
- Keep npm scripts cross-platform (Windows): no bash-only syntax in `package.json`.

## Invariants (details in `docs/DECISIONS.md`)

- **Saves** are versioned (`src/gameplay/sim/save.ts`): bump `SAVE_VERSION` with a migration step for every state change, never drop progress; `repairTrainingQueue` runs on every load; one writer per village (save revisions, `SaveConflictError`); a damaged save is kept and offered back; a save from a newer build stops the boot.
- **Battles** replay exactly from seed + deployments with only + − × ÷ and √, at 10 ticks/s. Combat data or rules change → bump `SIM_RULES`, and run `npm run rules:snapshot` **before** the bump so the server keeps the old rules; records carry their rules and other replays show as unavailable. Combat numbers never ship in balance bundles. Deploy the server before the game.
- **The server owns online truth:** it issues battle seeds, re-simulates every battle (worker threads), replays held villages' commands (`PLAYER_COMMANDS`, `economyHash`), checks store receipts, and applies the under-18 cap. Database changes are new numbered migrations, never edits. Protocol changes go in `docs/PROTOCOL.md` with contract tests.
- **Honesty:** generated opponents (the computer rival clans), simulated raids and generated Gangs are always labelled as such. Close-call notes only when true; a chest only shows what it gave.
- **Money and minors:** real prices only in the Store and its confirm step, a clear confirm on every purchase, the under-18 monthly cap, no offers that pop up for minors or unknown ages, Jade buys resources only as a top-up for one action. Nothing random is sold; the daily chest, streak repairs, the 28-day calendar, ability charges and trial rewards are never sold. Paid random items would need odds shown first and each market's loot-box law checked.
- **Return hooks stay ethical:** notifications off until the player says yes, every type switchable, quiet hours, `maxPerDay`; event countdowns are real; a missed day never wipes a streak or a calendar.
- **Privacy:** play statistics only from adults who opt in, under a random id; crash reports opt-in; age bands only get stricter; account deletion clears every player-owned table.
- **Text:** new interface text goes through `t()` (`src/presentation/ui/i18n.ts`) with its English in `locales/en/ui.json`, plurals as keyed ICU messages; game data text comes from `src/gameplay/data` (`npm run i18n:extract && npm run i18n:sync` after changes). Names in any script go through `sim/social/names.ts` and are isolated in sentences.
- **Identity:** display names come from `src/gameplay/data/*.json`; internal ids never change.

## Checks

`npm test` (includes the boundary and status tests), `npm run build`, `npm run typecheck:server`, `npm run server:build`; `TEST_DATABASE_URL`/`TEST_REDIS_URL` run the Postgres/Redis tests (CI's Server release workflow does). After costs, times, loot or combat numbers change: the model-player and balance tests in `tests/gameplay/balance/`, `npm run balance:armies`, `npm run balance:campaign` (about three minutes; `campaign-gates.test.ts` holds its results to lower and upper bounds and fails while they are stale). After changing the numbers in `docs/STATUS.md`'s table: `npm run status`.

## Stack

Phaser 3.90 (the production build bundles `render/phaserBuild.js`, not all of Phaser), Vite 8, Vitest 5, TypeScript 5.9, plain DOM + CSS HUD. Server: Fastify, `pg`, optional Redis through a small hand-written client, Sentry envelopes without the SDK. Owner-only steps (store accounts, products, secrets, hosting) are in `docs/SHIPPING.md`.
