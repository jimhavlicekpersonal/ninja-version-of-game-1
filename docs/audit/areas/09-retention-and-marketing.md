# Kagemura growth / retention / marketing audit (read-only, 2026-11-05)

Scope: ethical addictiveness, marketing, and a PM "what's missing" sweep. Evidence is file:line from the current tree. VERIFIED = read in code/docs; SUSPECTED = inferred, needs a human or device check. Severity is for revenue/retention impact, not code risk.

## A. Findings

### Measurement (you cannot run a launch blind)

**1. [Critical, VERIFIED] Analytics never leave the device, so D1/D7/D30, funnel and ARPDAU are uncomputable.**
Evidence: `src/backend/analytics/events.ts:1-122` (IdbEventStore writes to IndexedDB, max 5,000 events, `recent()` only; no network code anywhere); the only consumer is Settings → Advanced → "Analytics events (this device)" `src/presentation/ui/hud.ts:1854`; `docs/store/PRIVACY.md:31` ("the device only; never sent"). The server has no per-player activity metric either: Prometheus counters are errors/battles/purchases/refunds (`server/app.ts:158-200`, `server/core/pvp.ts:467-477`, `server/core/purchases.ts:249-279`), none is "sessions" or "active players".
Why it matters: every launch decision (soft-launch kill criteria, phased rollout, store ROI) needs cohort retention and funnel drop-off. Right now the owner will learn retention only from store-console aggregates (Play "active users" and App Store "sessions"), which cannot tell where the tutorial loses players.
Change: add an opt-in-by-design but *default-on, pseudonymous, non-personal* telemetry path (one new `POST /v1/analytics` batch endpoint with the existing player id or a rotating install id, the 18 event names already defined, `tutorial_step`, `session_start`, `raid_end`, `purchase`), gated by a Settings switch, declared in both privacy forms as "App activity → App interactions, not linked to identity". Under GDPR/UK Children's Code the honest options are: (a) product-analytics under legitimate interest with easy opt-out (common, defensible for non-identifying events), or (b) opt-in. Pick (a) for ages 18+, off-by-default for under-18 bands (the band already exists: `src/gameplay/sim/age.ts`). Update `docs/store/PRIVACY.md` rows 31/60 and `public/privacy.html` in the same commit. Then a nightly job on the server computes D1/D7/D30 by install cohort and tutorial step funnel. Without this, no soft launch is possible.

**2. [High, VERIFIED] Crash reporting is opt-in and off by default, so the owner will have near-zero crash visibility at launch.**
Evidence: `src/backend/platform/prefs.ts:10` `PREF_DEFAULTS = { crashReports: false }`; `hud.ts:1775` "Send crash reports (off until you turn it on)"; `docs/store/WORLDWIDE_AUDIT.md` GLOBAL-019 made this the default to match declarations. `docs/store/RELEASE.md` "Watch during the rollout: Crash-free sessions (Sentry...)" will show ~nothing.
Why: a WebView game on 2 GB Androids will crash; Sentry with <5% opt-in cannot catch regressions in time for a staged rollout halt.
Change: rely on the stores' own crash tools (Xcode Organizer / Play Vitals) which need no consent, and state that in RELEASE.md; or make crash reports default-on for adults only with the already-sanitized envelope (no name/id/save, `src/backend/analytics/crashReports.ts:1-8`) and update the privacy label ("Crash data, not linked"). Either way, add "Play Vitals / Xcode crashes" to the rollout watch list.

**3. [High, VERIFIED] No A/B or cohort capability.** Balance bundles are one global signed patch per data version (`src/backend/net/balanceBundle.ts:30-41`: `id, rules, base, changes, dataVersion, signature`; no cohort/percent/segment field). Offers are static rules (`src/gameplay/data/offers.json`).
Why: you cannot test price points, pack sizes, tutorial copy or chest tables without an app release and without a measurable split.
Change: add `cohort: { salt, percentFrom, percentTo }` to the bundle and let the server serve one bundle per cohort (player id hash); combined with finding 1 this gives price/pacing A/B without code pushes. Keep combat excluded as today.

### First session and core loop

**4. [Medium, VERIFIED] Core loop is clear and time-to-first-raid is short (good).** Tutorial `src/presentation/ui/tutorial.ts:34-85`: 9 steps, Mint (10 s build, `buildings.json:...acorn_orchard buildSeconds 10`), Keep L2 (240 s, `buildings.json:20-24`), Dojo 10 s / Camp 22 s / Tower 22 s, Shinobi 20 s each (`troops.json` hedgehog_roller), first raid. With 500 starting Jade (`economy.json startingResources`) the whole thing is ~4-6 min, or ~2 min if the player taps Finish. The first raid is a labelled generated target. This is within genre norms (CoC ~3-5 min to first attack).
Risk: step 4 teaches "tap Finish now to use a little Jade" in the first 3 minutes. That is the industry pattern, but with a 240-second wait it is also the first "pay to skip" prompt; fine ethically because the wait is short and Jade is free, but track `tutorial_step` drop-off at `finishKeep` once finding 1 exists.

**5. [High, VERIFIED] The game has no fiction hook, no hero, no cast beyond one mentor portrait.** `WORLDWIDE_AUDIT.md:352` ("No story, cast, differentiation, empty world at launch: owner"); Sensei Hoshi appears only in tutorial bubbles (`tutorial.ts:34`, `uiArt.senseiPortrait`); heroes exist only as catalog entries (`roster.json:875`, `progression.json:491` Hero Hall), `docs/rebuild/HANDOFF.md` "Unfinished 2: There is no hero system yet".
Why: in this genre the icon, the store screenshots, the trailer and the ad creative all lean on 1-3 named characters (Barbarian King, Lords Mobile heroes). Procedural chibi silhouettes with role rings (`src/presentation/art/warriorIcons.ts`) are readable in play but do not sell an install. CPI for strategy is ~$4-5.5 on iOS/$4 Android per vendor blogs (see sources), and creative quality is the main CPI lever.
Change: before marketing spend, ship 1 playable hero (Shadow Captain is already designed) and give Sensei Hoshi + 3 rival clan leaders names, portraits and 2-line bios that appear in the scout screen of generated opponents ("Hollow" bases could be the rival clans' outposts). This also solves the "empty world" cold-start feel (finding 12).

**6. [Medium, VERIFIED] Progressive rail hides Events, Pass, Goals and Alliance until the tutorial is done or Keep 2** (`hud.ts:380-390`). Reasonable for clarity, but the Season Scroll and Goals (which carry the first free Jade: `achievements.json` tiers 10/25/50 Jade) are also the first "reasons to come back tomorrow" and should be surfaced in the tutorial's closing step (`tutorial.ts:85` "end" step mentions only Dojo/Alliance). Add one line: "Your daily chest and Season Scroll are on the right."

**7. [Medium, VERIFIED] No "next objective" on the village screen.** HANDOFF "Next (progression flow): a clearer next objective on the HUD" is still open; the only "Next:" is inside the Codex (`hud.ts:1554`) and the Events pill. A suggested-army exists (`src/gameplay/sim/suggest.ts`) but there is no suggested *upgrade*.
Change: one persistent chip under the top bar driven by a pure `nextObjective(state)` in sim (next cheapest Keep-gating upgrade, or "army ready: raid", or "chest ready"), the single most effective D1-D3 retention UI in this genre.

### Return mechanics (10 min / 4 h / next day)

**8. [High, VERIFIED] Notifications are off by default, no prompt at the moment of value, and two high-value types are off even after opt-in.** `prefs.ts:10` `reminders: false`; `notifications.json` `dailyChest.default: false`, `events.default: false`; Settings copy `hud.ts:1757` "(off until you turn it on)". No in-flow ask found (grep `requestPermission` hits only `main.ts:387` error toast). Ethically correct and matches the listing claim, but the genre's D1 engine is the "your Keep is ready" push.
Why: with 4-session/day play the model player reaches Keep 5 by day 4 (`docs/game-theory/CAMPAIGN.md`), but casual one-visit players take 11.7 days; the difference between those two curves is mostly reminders.
Change (ethical, store-compliant): keep the master switch off, but ask once, in context, right after the first long timer starts post-tutorial ("Want a nudge when the Keep finishes? Only timers you start, never offers, quiet hours respected") with a real system prompt; and make `dailyChest` default-on once the player opts in (it is the player's own free reward). Measure opt-in rate (finding 1).

**9. [Medium, VERIFIED] All daily resets are UTC midnight.** `src/gameplay/sim/pass.ts:16` `dayIndex`, `daily.ts:42` `nextChestAt`, `stipend.ts:3` "per UTC day", seasons `ranks.ts:33` UTC month, Alliance War `social.json:168` fixed epoch. UTC 00:00 is 09:00 JST / 08:00 Beijing / 05:30 IST / 19:00 EST / 16:00 PST.
Why: in East Asia the chest and tasks reset during the morning commute (fine), but in the Americas they reset at dinner time: a player who does tasks at 20:00 EST sees them reset mid-session, and "tomorrow's chest" is 4 hours away, which trains players to double-dip late evening rather than return next morning. Task "days" (`pass.ts` daily tasks) ending at 19:00 local is the real retention cost.
Change: keep the chest's UTC day (anti-reroll needs a fixed seed), but either (a) roll task days on the device's local midnight for device villages (server-held villages: store the player's tz offset, already sent for push `main.ts:275`), or (b) move the global reset to ~06:00 UTC which hits most populations at night/early morning (01:00 EST, 22:00 PST previous day, 15:00 JST is the worst case). Decide with the first soft-launch geography (finding 30).

**10. [Medium, VERIFIED] Live-ops content cadence is thin: 4 distinct events, 5 slots, 14-day loop.** `src/gameplay/data/events.json`: Harvest Festival (+30% collect), Night of Raids ×2 (+20% loot), Swift Feet (−25% training), Bounty Hunt (the only playable goal event, `goalEvents.ts`). A player sees every event by day 14 and the schedule verbatim by day 28; the audit marks "Trial tower and Gang shared goal specified only" (`WORLDWIDE_AUDIT.md:349`). Events are also hidden until Keep 2 (finding 6) and cannot be changed without a data release (combat-free fields *can* ship as a balance bundle: `SHIPPING.md` 3j).
Why: D30+ retention in this genre is carried by a visible monthly calendar of distinct events and a seasonal theme. Three passive multipliers are not content.
Change: (1) make the schedule server-delivered through the balance bundle so the calendar can change monthly without a release (events.json is data, non-combat); (2) add 3 more goal-event kinds reusing existing systems: Trial Sprint (clear N tiers, uses `trials.ts`), Clan Rally (Alliance-wide donation/star goal, uses grove XP), Defender's Week (hold N raids, uses `defensesWon` stat); (3) an "Events calendar" view listing the next 4 windows (the data already exists: `upcomingEvents`).

**11. [Low, VERIFIED] No seasonal/holiday theming at all.** Cosmetics are 5 Keep roof palettes (`cosmetics.json`), one pass-only; 3 purely decorative buildings (`buildings.json:2210-2244`: pine, stone lantern, gravel). No Obon/New Year/Lunar New Year/Halloween skins or event names. Zero cost to add via data + the code-drawn art (`ninja.ts` palettes). Needed for featuring (Apple/Google feature holiday content) and for the Japan/Korea markets listed in `docs/legal/MARKETS.md`.

**12. [High, VERIFIED] Cold-start: a PvP game whose server falls back to generated bases, labelled as such, on day one.** `server/core/pvp.ts:261,305,318` ("otherwise a generated base of matched strength", `kind: 'bot'`); offline the Alliance is "computer players" (`groveUi.ts:151`), raiders "(simulated raider)" (`hud.ts:1679`), Gang War "a labelled generated Gang when nobody fits" (CLAUDE.md). Honesty is correct and will pass review; but the store listing sells "Raid rival clans / Play together", and with a few hundred installs spread over 15 Keeps and a `powerSlack` 0.25 window, most raids will say "Generated" for weeks.
Why: the first thing a reviewer or YouTuber will write is "it's all bots".
Change: (1) reframe the fiction so generated opponents are *named rival NPC clans with leaders* (ties to finding 5), labelled "Rival clan (computer)" rather than "Generated"; (2) seed the ladder: `docs/backend/PVP_ROADMAP.md` has no "seed bases" step, so add a server job that publishes a bank of real-looking player bases per Keep (from `showcaseVillage.ts`) under NPC clan names so matchmaking finds "player" bases at every Keep; (3) concentrate launch geography (finding 30) so real players cluster; (4) do not promise "weekly Alliance War with real players" in the first listing; say "Alliance Wars" only.

### Social and viral loops

**13. [High, VERIFIED] No referral reward, no invite incentive, and the only share surface is the friend code.** `src/presentation/ui/friendsUi.ts:233-262` (`?friend=` link, QR, `navigator.share` with text "Add me in Kagemura"); `main.ts:402` friend link base needs `VITE_PUBLIC_URL` in native builds (audit R09 open: links open the *web* game, not the store/app). No referral code redemption, no reward for either side (grep "referr" = 0). Gang invites are friends-only dropdown (`gangUi.ts:146-152`).
Why: k-factor is the cheapest install source for a social base builder; Gangs of 2-4 friends are *designed* for invites but there is no reason to send one.
Change: add a "Recruit" achievement tier (both sides get a fixed Jade grant once the recruit reaches Keep 3; server-verified, capped at 10, not random, so it stays within the "nothing random sold" claim), a share sheet with a pre-rendered image of the player's village (canvas → PNG, `navigator.share({files})`), and finish R09 (App Links / Associated Domains) so a link installs the app.

**14. [Medium, VERIFIED] Replays are local-only; nothing can be shared or spectated.** `hud.ts:1631-1638` Replay button only; server keeps replays 30 days (`server/core/retention.ts:17`) but there is no public replay URL. No spectate, no "share this battle" after a 3-star, no close-call share (closecall.ts exists but only shows text).
Why: creator/influencer readiness is zero: a YouTuber cannot link a fight; the strongest organic creative in this genre is a 15-second 3-star clip.
Change: a signed read-only replay token (`GET /v1/replays/:id` already stores by hash) opened by the web build at `?replay=`, plus a "Share battle" button on the result screen that uses the Web Share API with the link; later, in-game MediaRecorder capture of the battle canvas to a short video (web and Capacitor both support `canvas.captureStream`).

**15. [Medium, VERIFIED] The leaderboards are buried in Settings.** Honor and Power Ranking render inside a `<details>` in Settings → Online play (`hud.ts:544-621`), top 30, global only; no country or friends filter (`protocol.ts:648-670` LeaderboardEntry has no country). No profile page/nameplate/avatar: a player card is name + Keep + league + alliance (`friendsUi.ts:268-278`).
Change: move the ladder to a rail button once online, add a Friends tab and a per-Alliance tab (both are cheap: data already in the Friends and Grove responses). Country leaderboards need a self-declared flag (not IP, to keep the privacy label clean); treat as later.

**16. [Low, VERIFIED] Social obligation loops exist but are weak.** Alliance War is weekly, 48 h, 2 attacks (`social.json:168-171`); donation requests exist (`groveUi.ts:241-264`); Gang Wars 2 h prep + 22 h. There is no "clan perks" progression (grove XP levels exist, `social.json xpLevels`, but grep found no perk table), no clan games, no clan capital-style shared build. Request-to-donate push `donations` defaults off (`notifications.json`).
Change: turn `xpLevels` into 3-4 visible Alliance perks (donation refund %, +1 Lodge capacity, war chest +10%) so joining and donating has a reason beyond XP, and default `donations` push to on after opt-in.

**17. [Low, VERIFIED] No global chat, mail/inbox, news panel or in-game help.** Only Alliance and Gang chat; moderation notices are the only "inbox" (`hud.ts:936-955`); `SERVER_NOTICE` shows in Settings only (`RELEASE.md` "Tell players: set SERVER_NOTICE... shown in Settings → Online play"); help is the external `support.html`. A news/inbox panel is where live-ops announcements, patch notes, event previews and compensation grants land; without it the owner has no broadcast channel except push.
Change: a small `notices` extension (the server already has `features: 'notices'`) with kinds `news | reward` and a rail badge; reuse `drawNotices`.

### Progression, meta and monetization

**18. [High, VERIFIED] A 28-day casual wall at Keep 5→6 lands exactly where D30 is measured.** `docs/game-theory/CAMPAIGN.md` casual: Keep 5 at day 11.7, Keep 6 at day 39.7 (explorer policy: 13.7 → 39.7); `WORLDWIDE_AUDIT.md:348` "casual 5→6 still ~26-28 days: partly". Regular (4 sessions/day) reaches Keep 6 at day 10.4.
Why: the casual segment is the majority of installs; a month without a Keep level means no new buildings, no new warriors, repeats of 4 events. This is a churn cliff.
Change: product, not just numbers: give Keep 5 players a horizontal goal (hero unlock at Keep 5, cosmetics from achievements, Trial milestones with named rewards), and add a "catch-up" Season Scroll free track that pays Keep-6 shortfall resources around day 20. Then re-run `npm run balance:campaign` and target casual Keep 6 by ~day 20-24.

**19. [Medium, VERIFIED] Daily chest and streak are well-designed and compliant, but the 7-day streak pays only 5 Jade at the top and then stays flat** (`daily.json` steps 1.0→1.6× + 5 Jade at step 7; `daily.ts:55-71` holds at step 7). There is no weekly/monthly login calendar with a visible "big" reward (e.g. a hero skin at day 28), which is the standard, non-random, retention calendar in this genre.
Change: a 28-day calendar (fixed, non-random, never sold, one claim per UTC day) with a cosmetic at day 28; it fits the existing "nothing random is sold" claim.

**20. [Medium, VERIFIED] Monetization depth is sound but narrow.** Packs $0.99-$99.99 (`store.json:3-45`), Season Scroll $4.99 with honest "≈ N Jade" (`pass.ts:62-100`), Clan Stipend $2.99 consumable (`stipend.ts`), 3 live offers with `minAccountHours: 24` and `maxPerSession: 1` (`offers.json`), extra Artisans bought with Jade (`village.ts:417`). Missing vs genre: a one-time "Starter" at first long wait exists but there is no Keep-level progression bundle (sold once per Keep, the top-grossing offer type in CoC-likes), no cosmetic shop beyond 4 roof colours, no "gold pass" style builder boost beyond the pass's 20%.
Change: Keep-up bundles (one per Keep 3-10, contents = `productGrantsFor` scaled, `oncePerKeep`), 3-5 more cosmetics (Keep skins by season, warrior trails) purchasable with Jade only, keep every price shown in store currency (GLOBAL-007).

**21. [Low, VERIFIED] Under-18 players never see offers (`MARKETS.md` "offers never pop up for players under 18") and the age band is self-declared one-way.** Good for compliance; note for the forecast that a 13+ rated game whose teen players see no offers will have lower ARPDAU than genre benchmarks; model it.

**22. [Low, VERIFIED] Collection/mastery is present but not celebrated.** Codex "N of 50 unlocked", role/tier filters (`hud.ts:1530-1596`); Mastery EXP "in the model and docs but not tracked in the live game" (HANDOFF Unfinished 3). No unlock ceremony beyond the Army list; no "new warrior!" moment with a portrait. Cheap win: a modal on first unlock of each warrior with its badge and one-line role tip.

### ASO, store presence, web

**23. [High, VERIFIED] No landing page, no Open Graph/Twitter cards, no manifest screenshots.** `index.html` has only `description`/`theme-color` (grep `og:` = 0); the root URL boots the game directly; `public/` holds only legal pages; `public/manifest.webmanifest` lacks `screenshots`, `description` is fine but there are no `shortcuts`. **24. [Medium, VERIFIED] Store listing is English-only, screenshots have no captions, and the asset pipeline stops at raw screens.** `docs/store/LISTING.md:84-88`: keep screenshots English; `tools/store/screenshots.mjs:69-74` captures 1-village, 3-army, 4-store, 5-alliance plus a battle shot, with no caption/frame overlay; the Store shot shows the sandbox note. `locales/` worksheets are 0/648 for every language (`npm run i18n:status`). Change: add a caption/frame stage to `screenshots.mjs` (headline per screen, phone frame), a `feature-graphic` target in `brand.mjs`, and translate the 6 listing strings into wave-1 languages even while the game stays English (say "English only" in the description's last line).

**25. [Medium, SUSPECTED] Keyword and title choices are generic; the icon is a landscape, not a character.** Keywords `LISTING.md:46` "ninja,clan,village,strategy,base builder,raid,defense,tower,shinobi,war,alliance,castle,samurai" include words already in the title/subtitle (Apple ignores duplicates: "ninja", "clan", "village"), wasting ~20 of 100 characters; "castle"/"samurai" are off-theme. Change: drop duplicates, add long-tail intents ("base building", "war strategy", "clash", "kingdom", "empire", "pvp", "offline"), and A/B the icon (Play Store listing experiments) between the landscape and a masked-ninja character once finding 5 gives you one.

**26. [Medium, VERIFIED] No in-app review prompt and no "rate us" at a high-affect moment.** grep for `requestReview`/`SKStoreReviewController`/`ReviewManager`/`navigator.share` = only the friend share. Capacitor has no first-party plugin but `@capacitor-community/in-app-review` wraps both APIs.
Change: ask once after the first 3-star online win or Trial tier 5 clear, never after a loss or a purchase, max once per 90 days (Apple limits to 3/365).

**27. [Low, VERIFIED] Update prompting is sound** (`src/backend/pwa/register.ts`, "Update Kagemura" to store URLs `main.ts:210-213`, `426 version_mismatch`). No issue; just make sure `VITE_APP_STORE_URL`/`VITE_PLAY_STORE_URL` are in the release checklist (they are not listed in `RELEASE.md`).

README markets the PWA install path for all three devices.
Why: web is a great funnel (instant play, zero CPI, links unfurl, creators can embed), but only if it converts to the app where money is.

**29. [Low, VERIFIED] Healthy-play reminder after 60 minutes is on by default** (`prefs.ts:10` `sessionReminder: true`, `main.ts:547`). Good ethical signal; mention it in the listing's "Fair play" block for featuring pitches (Apple/Google editorial teams like it).

See section B.

## B. Marketing / launch human tasks (owner)

1. **Identity first (blocks everything):** trademark search "Kagemura" (roadmap step 2), final bundle id, domain with `/play` landing page, `assetlinks.json` + `apple-app-site-association` (R09). Decide on 1 hero + 3 rival clan leaders and commission or generate portraits (ART AI brief exists: `docs/art/ART_AI_BRIEF.md`).
2. **Store assets per language (wave-1: en, es, pt-BR, fr, de, ja, ko, zh-Hant, id, tr; skip zh-Hans/ru until markets are cleared):** title/subtitle/short description/keywords, 6-8 captioned screenshots at the 4 sizes `screenshots.mjs` already produces, a 1024×500 feature graphic, a 15-30 s app preview/trailer (vertical, first 3 s = a smoke-bomb 3-star), icon variants for a Play listing experiment.
3. **Pre-registration:** Google Play pre-registration (needs the listing + a pre-reg reward: a cosmetic Keep skin, non-random, delivered by a server grant on first login; add `prereg_skin` to `cosmetics.json`), Apple "pre-order" for the app. Run 3-6 weeks before launch; pre-reg converts 30-60% typically (verify with current Play docs).
4. **Community:** a Discord with #announcements/#replays/#bug-reports, a subreddit, one short-form channel (TikTok/YouTube Shorts) posting battle clips weekly (needs finding 14 for shareable links). Link them from `support.html` and the landing page; moderation staffing is already a legal item (R06).
5. **Soft launch (2 waves):** Wave A, 8-12 weeks: Philippines + Canada + Australia/New Zealand (English UI matches the English-only build; PH gives cheap installs for funnel/retention, CA/AU give tier-1 monetization signal; all are App Store + Play, no licensing issues in `MARKETS.md`). Wave B after fixes: add Brazil (pt-BR listing; ECA Digital is satisfied by "nothing random sold") and Turkey/Indonesia for scale, Japan only after the Tokushoho pages and native cultural review are done. Exclude mainland China, Vietnam, Indonesia-before-PSE per `docs/legal/MARKETS.md`. Pick server region near Wave A (Singapore or US-West).
6. **Budget order of magnitude:** soft launch $15-40k paid UA across both stores (≈5-10k installs at $3-5 CPI, enough for D7 confidence), plus $5-10k for creative production; global launch only if KPIs pass, then $100k+ with ROAS gating. Expect strategy CPI around $4-5.5 iOS / $4 Android in tier-1 (vendor figures, see sources).
7. **KPIs and kill criteria (soft launch, cohort of ≥3,000 installs, needs finding 1):** D1 ≥ 35%, D7 ≥ 15%, D30 ≥ 6% (strategy genre; the GameAnalytics 2025 medians are far lower, ~22%/4%, so these are top-quartile-ish targets appropriate for a UA-funded title); tutorial completion ≥ 70%; first raid ≥ 60% of installs; payer conversion D7 ≥ 1.5%, ARPDAU ≥ $0.08 in CA/AU; crash-free sessions ≥ 99.3% (Play Vitals). Kill/pivot if D1 < 25% or tutorial completion < 50% after two fix iterations.
8. **Review/rating response plan:** reply to every 1-2★ review within 48 h with a support link; watch for "all bots" and "pay to win" themes; collect support mail at `supportEmail` (currently unset in `legal-config.js`).
9. **Cross-promotion:** none available (single title); note the web build and a Discord are your only owned channels.

## C. Big-picture assessment

Would this retain and monetize against genre norms? **Systems, yes; product, not yet.** The simulation, economy, anti-cheat, compliance and ethical-engagement scaffolding are far ahead of a typical indie base builder, and the ethical choices (no loot boxes, honest countdowns, opt-in reminders, real odds, no faked near-misses) are a marketable identity. But the game is currently a *mechanism without a face*: no hero, no rival cast, no story, generic icon, 4 repeating events, a 28-day casual wall at Keep 5, bots labelled as bots in a PvP ladder that will be empty on day one, no referral/share loop, and, decisively, no way to measure any of it. Against commercially marketed strategy titles it would likely land below median on D7 (thin mid-term goals) and below median on ARPDAU (narrow offer set, teens see no offers), while the ethical design probably lifts long-tail retention and reviews.

**Five highest-leverage product changes, in order:**
1. **Measurable funnel and retention** (findings 1-3): pseudonymous event export with consent model, cohort A/B on balance bundles, store crash tools in the rollout plan. Nothing else can be judged without it.
2. **A face for the game** (findings 5, 12, 25): one playable hero, named rival clans whose leaders front the generated bases, character-led icon/screenshots/trailer. This fixes cold-start perception and CPI at once.
3. **Return hooks that respect the ethics already chosen** (findings 7-9, 19): a persistent next-objective chip, a contextual one-time notification ask with daily chest on by default after opt-in, local-midnight task days, a 28-day non-random login calendar.
4. **Mid-term content** (findings 10, 11, 18): server-delivered event calendar via balance bundles, 3 more goal-event kinds, seasonal cosmetics, horizontal goals that bridge the Keep 5→6 month.
5. **Viral and creator loops** (findings 13-15): referral achievement, shareable replay links and battle clips, leaderboards out of Settings with friends/alliance tabs, App Links so shares install the app.
