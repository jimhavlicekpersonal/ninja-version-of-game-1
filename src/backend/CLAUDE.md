## Monetization and compliance (keep these rules)

- Payments go through `PaymentProvider`: mock (testing sandbox only), StoreKit 2 (iOS, `ios/App/App/TkStorePlugin.swift`), Play Billing (Android, `TkBillingPlugin.java` on Play Billing Library 9.1.0, `android/variables.gradle` `playBillingVersion`; Play refuses 7.x. **Off unless the build sets `VITE_PLAY_BILLING=1`**: the Android workflow's signed release AAB sets it, the debug APK does not). `PaymentProvider.prices` gives the store's own formatted price, currency and micros per store product id (Play: `getProducts` → `OneTimePurchaseOfferDetails`); a product the store did not return is missing. Android release identity: `android/app/release.gradle` (`versionCode` from `-PtkVersionCode`/`ANDROID_VERSION_CODE`, CI = run number + `ANDROID_VERSION_CODE_OFFSET`; upload-key signing from `ANDROID_KEYSTORE_*` env or `android/keystore.properties`). Public web purchases stay disabled; ask the owner before adding a web payment path.
- Real prices only in the Store and its confirm step. Clear confirm on every purchase (FTC/Epic lesson). Under-18 spending cap. Chat filter on.
- Paid random items need their odds shown before purchase (App Review 3.1.1), and the loot-box laws in each market must be checked first. The daily chest is free and never sold. Streak repairs, ability charges and trial rewards are never sold.
- New app identity: the display name is "Kagemura". The bundle id is still `com.toadstoolkingdoms.app` (a new one means a new App Store / Play listing: owner steps in `docs/SHIPPING.md`). Store product ids come from `store.json` `storeProductIds` (the game's own ids never change).

## Checks

`npm test` (server tests use memory; set `TEST_DATABASE_URL` for Postgres and `TEST_REDIS_URL` for Redis), `npm run typecheck:server`, `npm run server:build`, `CONTRACT_URL=… npm run test:contract` against a deployed server. On the host: `npm run server:migrate` (release step) and `npm run server:bench` (re-simulation timing). The roadmap's step list (`docs/backend/PVP_ROADMAP.md`) marks what is done; owner steps stay unticked with what was prepared for them.

Names use the shared `sim/social/names.ts` validator. Use `censorText` for name moderation (unique player names reject blocked words), never chat’s `filterText` limit: a valid 24-grapheme Indic name can exceed 160 code points. Isolate names when constructing system messages or appending labels such as `(you)`.

Client runtime (client re-audit, 2026-11-05): `pwa/boot.js` is inlined first into `index.html` (`vite.config.ts` `bootGuard`; ES5 only): polyfills (`structuredClone` for plain data, `.at()`, `Object.hasOwn`), a feature check that shows "needs a newer browser", and a load guard ("Couldn't load Kagemura" + Retry on a failed or broken module; "taking a long time" after 25 s without a start-up step (`__tkBoot.progress`), added under the splash and removed when progress resumes, report section 5 step 3; the second Retry in a session also unregisters the service worker and deletes `tk-` caches when online). `main.ts` sets `window.__tkStarted` and calls `__tkBoot.done()` at the first village frame (`stop()` from its own error screen, which offers Retry/Update and "Copy save code" for a newer save). `persist/idb.ts`: `openGameDb` gives up after `IDB_OPEN_TIMEOUT_MS` (5 s; the game then runs on memory with a banner) and returns a reconnecting handle (`close`/`versionchange`/`InvalidStateError`/`UnknownError` reopen it; `transact` retries once; `main.ts` retries the save store's write through `reconnected`). The service worker installs hashed `/assets/` files through the HTTP cache (`cacheModeFor`: `default` first, `reload` on retry; everything else `reload`), so a first visit downloads the game once. `pwa/register.ts` `updateWebApp`: save, `registration.update()`, wait for the new worker (45 s), then reload, or say no newer version is out (no reload loop). `Connection.start` listens to `online`/`offline`/`visibilitychange` (`syncSoon`, at most every 5 s; `stop` removes them). StoreKit/Play `prices` give up after 10 s; the shop keeps prices only after a complete answer and asks again on the next opening. `main.ts` checks `navigator.storage.persisted()`/`persist()` and, when refused (Safari outside the Home Screen), shows a banner at most once a week (`tk.persistPromptUntil`) and a note in Settings (Add to Home Screen, a linked sign-in, a save code). Android Back goes through `@capacitor/app` (registered in `android/capacitor.settings.gradle`, `android/app/capacitor.build.gradle`, `ios/App/CapApp-SPM/Package.swift`; `npx cap sync` regenerates them): top dialog or sheet, then the battle's own End battle / Home, then a "Leave Kagemura?" confirm and `exitApp`. Device behaviour (Back, Safari eviction, iOS IndexedDB loss, real update flow) is not verified on devices.
