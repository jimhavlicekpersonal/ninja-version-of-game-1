# Lessons from the last build

What went wrong while Kagemura was built and audited, and what the factory does so the next game does not repeat it. Source: the template's own audits and history (`docs/audit/`, `docs/store/WORLDWIDE_AUDIT.md`, `docs/history/`, `docs/rebuild/`). The template's blueprint may add newer ones.

| What happened | Why it hurt | What the factory does |
|---|---|---|
| The game was built first and its market asked about last. Three audits later it was "technically serious, not yet a product": no hero, no cast, no story, a generic icon. | A faceless game in a crowded genre has nothing to put on a store page. | Market and brand come first. The brand stage must deliver a cast with faces, a premise and an icon idea before any system is touched. |
| Monetization was honest and under-priced: free premium currency each month equalled the mid-size pack; a small recurring product gave three times the value of any pack; the starter offer was usually lost; offers never reached players who had not declared an age. | Ethical is not the same as viable. Nobody did the sums. | The monetization stage shows the arithmetic of free against paid, checks every offer trigger can actually fire, and hands the economy stage explicit requirements. |
| Paying could make the game worse (rushing the main building met stronger opponents). | The best customers were punished. | Rule in the doctrine; the economy stage lists it under exploits to guard. |
| Every publisher fact on the legal pages was empty, so the game could not be listed in the EU, UK, Japan or Germany, and nothing in code could fix it. | The owner backlog (about 80 items) was found after the engineering was "done". | Every stage lists owner tasks; the skeleton gathers them into one page before the owner approves. |
| Interface text was hard-coded in English and the text layer came late, so translation was blocked, then redone. | Rework across 50 languages. | The template now has the text layer. The doctrine keeps every string in it; the languages stage writes the glossary before the first string is rewritten. |
| Leftovers of the previous theme reached players: old assets, the old package name, old product ids in the store test file. | A reviewer sees them first. | The build ends with a leftover hunt driven by the template's theme words and the ID map. |
| "Fixed" and "done" in summaries did not hold when re-checked; documents disagreed with code on versions; three audits in a day produced 42 documents. | Sessions fixed things that were not broken and trusted statuses that were stale. | One generated status file, one game bible, and closure records with evidence. The harness runs the checks itself; a session's word is not a pass. |
| CI was green while two of its jobs did nothing (no signing key, no deploy target). | Green-washing. | A skipped check is reported as not run, never as passed. |
| Everything was verified in a desktop browser. Texture memory grew without limit and would have killed cheap phones. | The riskiest items cannot be seen in emulation. | The engine stage sets budgets and lists device checks as owner tasks; nothing is called device-ready by code. |
| Balance was measured by model players: a dip on day two, a four-week wall where day-30 retention is measured, late-game casual players losing most raids, defense never worth building. | Pacing problems land exactly where retention is counted. | The economy stage states pacing targets against what the template measures, and the build keeps the balance gates (lower and upper bounds) green. |
| The device-to-server bridge was the economy's soft spot: forged imports, clock skipping, refunds after spending, purchases around the minor's cap. | Each one is real money or a ruined ladder. | The server owns online truth (doctrine); the economy stage lists the exploits each new mechanic opens. |
| A new mechanic was nearly not part of the replay stream. | The server would have disagreed with the client on every battle. | Anything that changes a battle is a deployment in the stream, with the rules version raised and the old rules archived first. |
| The theme sat close to famous franchises (hidden villages, rank ladders, headbands, spiral symbols). | Legal and store risk. | The brand stage names the nearby franchises for the chosen theme and how the game stays clear of each. |
| The name had a plausible meaning as a surname and place name in a launch language, and no trademark search had been done. | A rename after launch is a new app. | The brand stage searches for conflicts and meanings, keeps fallback names, and leaves the formal trademark search as an owner task. |
| Daily resets were at UTC midnight (dinner time in the Americas); notifications had no ask at the moment of value; four events repeated every two weeks. | Small frictions that add up to churn. | Local-midnight days, the contextual ask and a longer calendar are in the template now; the economy stage plans a year of events in the new fiction. |
| The free web build was both the best funnel and a revenue leak, and nobody had decided its role. | Marketing could not start. | The market stage decides what the browser build is for. |
| Parallel sessions collided in shared hot-spot files. | Lost work. | One lane per session, contract files, request files; the factory's write tools refuse paths outside the lane. |
